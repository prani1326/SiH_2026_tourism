# 🌍 Travel Company Vendor / Guide Backend API (Firebase Architecture)

Backend API service for the **Travel Company Vendor/Guide Android App** and **Admin/Staff Verification System**, built with **Node.js, Express.js, Firebase Admin SDK (Firestore, Authentication, Storage, FCM)**, role-based authorization, and Multer.

---

## 🏛️ System Architecture

```text
Vendor Mobile App (Android) / Web Dashboard
                  ↓
       Node.js + Express Server
                  ↓
          Firebase Admin SDK
                  ↓
       ┌──────────────────────────────┐
       │     Firebase Platform        │
       ├──────────────────────────────┤
       │ • Firestore Database (NoSQL) │
       │ • Authentication             │
       │ • Cloud Storage              │
       │ • Cloud Messaging (FCM)      │
       └──────────────────────────────┘
```

> **Note**: SQLite and other local databases have been completely removed. Firestore is the sole database platform.

## 🚀 Quick Start

### 1. Install Dependencies
```bash
npm install
```

### 2. Configure Firebase Environment
Copy `.env.example` to `.env` and configure your Firebase credentials:
```bash
cp .env.example .env
```

Set either `FIREBASE_SERVICE_ACCOUNT_PATH` pointing to your service account key file:
```env
FIREBASE_SERVICE_ACCOUNT_PATH=./firebase-service-account.json
```
Or set individual credentials:
```env
FIREBASE_PROJECT_ID=your-firebase-project-id
FIREBASE_CLIENT_EMAIL=firebase-adminsdk-xxxxx@your-firebase-project-id.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
FIREBASE_STORAGE_BUCKET=your-firebase-project-id.appspot.com
```

### 3. Seed / Migrate Data into Firestore
Populate all collections with production defaults or restored backups:
```bash
npm run seed
# or
node scripts/migrate_to_firestore.js
```

### 4. Run Automated Integration Tests
Execute the 16 comprehensive integration test suites:
```bash
npm test
```

### 5. Start Development Server
```bash
npm run dev
# Server will start on http://localhost:5000 (binds to 0.0.0.0 for Android emulator 10.0.2.2)
```

## 🛡️ Authentication & Vendor Isolation (RBAC)

1. **Firebase Authentication Support**:
   - Accepts Firebase ID Tokens via `Authorization: Bearer <token>`.
   - Validated via `admin.auth().verifyIdToken(token)`.
   - Backward-compatible with internal signed JWT tokens.
2. **Vendor Data Isolation**:
   - Authenticated middleware injects `req.vendor` based on the verified token.
   - All vendor routes scope data queries exclusively to `where('vendor_id', '==', req.vendor.id)`.
   - Vendors cannot view, edit, or delete another vendor's listings, bookings, trips, or wallet funds.
3. **KYC Feature Gate**:
   - Vendors with `pending` or `rejected` KYC status can access profile and KYC submission endpoints, but cannot publish listings, accept bookings, or operate trips.

## 📐 API Endpoints Summary

### Vendor Authentication (`/api/vendor/auth`)
* `POST /api/vendor/auth/register` — Vendor signup
* `POST /api/vendor/auth/login` — Login with email/mobile and password
* `POST /api/vendor/auth/request-otp` — Request 6-digit OTP
* `POST /api/vendor/auth/verify-otp` — Verify OTP code
* `GET  /api/vendor/auth/me` — Current vendor profile
* `POST /api/vendor/auth/logout` — Logout session

### Vendor Profile & KYC (`/api/vendor/profile`, `/api/vendor/kyc`)
* `GET  /api/vendor/profile` — Fetch profile
* `PUT  /api/vendor/profile` — Update name / email / details
* `POST /api/vendor/profile/photo` — Upload profile photo to Firebase Storage
* `GET  /api/vendor/kyc` — Fetch KYC details and documents
* `POST /api/vendor/kyc` — Submit personal, business, and tax information
* `POST /api/vendor/kyc/documents` — Upload documents to Firebase Storage
* `GET  /api/vendor/kyc/status` — Returns KYC approval status and remarks

### Tours & Listings (`/api/vendor/listings`)
* `GET    /api/vendor/listings` — List vendor tour packages
* `GET    /api/vendor/listings/:id` — Get tour package details + bookings
* `POST   /api/vendor/listings` — Create new tour package
* `PUT    /api/vendor/listings/:id` — Update package
* `DELETE /api/vendor/listings/:id` — Delete package

### Bookings & Orders (`/api/vendor/bookings`)
* `GET  /api/vendor/bookings` — Filter bookings by `pending`, `accepted`, `rejected`, `completed`
* `GET  /api/vendor/bookings/:id` — Get booking details
* `POST /api/vendor/bookings/:id/accept` — Accept booking & auto-create upcoming trip
* `POST /api/vendor/bookings/:id/reject` — Decline booking with reason

### Trips & Live Tracking (`/api/vendor/trips`)
* `GET  /api/vendor/trips` — List trips (`upcoming`, `active`, `completed`)
* `GET  /api/vendor/trips/:id` — Get trip details
* `POST /api/vendor/trips/:id/start` — **Start trip** (Turns Location Tracking **ON**)
* `POST /api/vendor/trips/:id/location` — **Record GPS coordinates**
* `GET  /api/vendor/trips/:id/location` — Get GPS trail points
* `POST /api/vendor/trips/:id/end` — **End trip** (Location Tracking **OFF**, marks completed, credits wallet)

### Wallet & Transactions (`/api/vendor/wallet`)
* `GET /api/vendor/wallet` — Balance, total earned, pending amount
* `GET /api/vendor/wallet/transactions` — Transaction ledger

### Notifications (`/api/vendor/notifications`)
* `GET  /api/vendor/notifications` — Notification alerts
* `POST /api/vendor/notifications/:id/read` — Mark notification read
* `POST /api/vendor/notifications/read-all` — Mark all read

### Admin Verification & Audit (`/api/admin`)
* `POST /api/admin/auth/login` — Admin login
* `GET  /api/admin/auth/me` — Staff profile
* `GET  /api/admin/vendors` — List verification queue
* `GET  /api/admin/vendors/:id` — Inspect KYC & documents
* `POST /api/admin/vendors/:id/verify-kyc` — Approve or Reject KYC
* `GET  /api/admin/audit-logs` — Administrative audit trail
* `GET  /api/admin/dashboard` — Platform metrics
